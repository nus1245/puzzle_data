## 4. 사용자 판단이 필요한 미결 사항

1. **TO-BE 감축률(표지 ▼64%, S13 "105.9h → 약 38h")의 산출 근거가 저장소에 없다.**
   - 노트북 Part 7의 36.0h / 65.1%는 하드코딩된 가정값(`to_be_phase = [0.5, 4.0, 12.0, 5.5, 0.0]`, 합계 22.0h ≠ 36.0h)이고, 105.9 → 36.0h는 −66.0%라 65.1%와도 맞지 않는다. 스토리보드의 38.0h(−64.1%)·"65%"도 출처가 없다.
   - 시뮬레이션으로 **검증된 값은 "실사 대기 20% 단축 → −15.4h → OLS 1.12 적용 −17.2h (−16.2%)"** 뿐이다.
   - 덱 처리: 표지·S13을 "목표(가정 기반) 약 64%"로 표기하고 검증 하한 −17.2h를 병기했다. 65%로 되돌리거나 38h의 근거를 별도 시뮬레이션으로 만들지는 직접 결정해 달라.
2. `docs/02_analysis_insights.md` Point 12 는 "단독 1.1h, 7.2배"로 적혀 있으나 원천은 1.20h, 6.6배이다. 이 문서는 수정하지 않았다.
3. SQL 주석 내부에서 CAPA가 69.2 / 63.7 / 68.0건으로 혼재한다(산출 구간 차이). 덱은 68.0건을 쓰고 63.7건(14일 지속, 소화율 47.2%)은 발표 노트에 방어용으로만 두었다.
4. 대면·우편의 "15분 이내 완료율"은 SQL 주석(99.6% / 51.7%)과 재계산(≤15분: 100.0% / 52.2%)이 다르다(노트북의 측정 시점 차이로 추정). 15분 이내 건의 평균(8.2 / 8.5 / 6.8 / 8.4분)은 일치하며, 덱의 S09 차트는 재계산 값을 쓴다.

## 6. HTML 판 구현 메모
- `scripts/deck_html.py` 는 `deck_common` 과 같은 함수 이름(add_text / add_box / add_pill / add_picture_contain / add_table …)을 HTML 로 렌더링한다. `scripts/build_html_deck.py` 가 `build_deck_v3.py` 를 수정 없이 실행하면서 모듈만 바꿔 끼우므로 **PPTX 와 HTML 의 좌표·문구·차트·발표 대본이 항상 동일**하다(13.333in = 1920px, 1pt = 2px).
- 한글은 `word-break: keep-all` 로 어절 단위 줄바꿈, 차트는 `object-fit: contain` 으로 종횡비를 보호하고 base64 로 내장해 파일 하나로 동작한다.
- 검증: Edge 헤드리스로 슬라이드 1·2·5·7·8·9·10·11·12·13·14 캡처 확인, `S` 시트(`#8,notes`) 확인. **`Ctrl+P` 인쇄(PDF) CSS 는 작성했지만 시각 검증하지 못했다.**
