## 🛠️ [1단계] 데이터 전처리 (Data Preprocessing)

### CASE 1. taskID 결측치(2건) 복원
* **상황 및 발상**:
  * `taskID` 결측치 2건 발생 (7124행, 7785행).
  * *발상*: 누락된 작업의 공통되는 `caseID`를 찾아 타겟으로 선정하고 시간순(`timestamp`)으로 작업을 나열하면 작업 결측치를 대체할 수 있지 않을까?
* **판단 (근거 및 분석)**:
  1. **7124행 (`caseID: 245`)**: 작업 흐름이 `[NaN (14:37, Web)]` → `MakeTicket start (14:37)`. 접수 채널(`contact: Web`)을 가진 점과 티켓 발행 직전 단계라는 점에서 최초 접수(`FirstContact`) 누락으로 판단.
  2. **7785행 (`caseID: 15`)**: 작업 흐름이 `ArrangeSurvey complete (Monica, 09:26)` → `[NaN (System, 09:26)]` → `Survey`. 조율 완료 즉시 System 자동 발송 단계라는 점에서 고객 설문 안내(`InformClientSurvey`) 누락으로 판단.
* **행동 (조치 및 실행)**:
  * `df.loc[7124, 'taskID'] = 'FirstContact'`
  * `df.loc[7785, 'taskID'] = 'InformClientSurvey'`
  * 행 삭제 없이 `taskID` 결측치 0건 달성 및 100% 무결성 확보.

* **판단 (전체 작업 라이프사이클 3대 분류 체계)**:
  1. **시작/종료 쌍(Pair) 업무 (5개)**: `start`와 `complete`가 1:1로 존재하여 소요시간(Duration) 측정 가능
     - `MakeTicket` (시작 927 / 완료 927)
     - `ArrangeSurvey` (시작 926 / 완료 927 / 결측 1) ➔ **6953행 `start` 복원**
     - `Survey` (시작 927 / 완료 926 / 결측 1) ➔ **8217행 `complete` 복원**
     - `ImmediateRepair` (시작 382 / 완료 383 / 결측 1) ➔ **9843행 `start` 복원**
     - `InternRepair` (시작 547 / 완료 547) ⭐ *사내 수리(결측 없음)*
  2. **단일 완료(Complete-only) 업무 (7개)**: 마일스톤 성격 (`start` 미존재)
     - `FirstContact` (1,000건), `InformClientWrongPlace` (73건), `RepairReady` (927건), `ReadyInformClient` (927건), `SendTicketToFinAdmin` (927건)
     - `InformClientSurvey` (완료 926 / 결측 1) ➔ **8144행 `complete` 복원**
     - `TicketReady` (완료 926 / 결측 1) ➔ **13159행 `complete` 복원**
  3. **단일 시작(Start-only) 업무 (1개)**: 외주 위탁 착수 시점만 기록 (`complete` 미존재)
     - `ExternRepair` (시작 132건, 완료 0건) ⭐ *외주사 핸드오프 시점만 기록*
* **행동 (조치 및 실행)**:
  * `df.loc[8144, 'eventtype'] = 'complete'`
  * `df.loc[13159, 'eventtype'] = 'complete'`
  * `df.loc[6953, 'eventtype'] = 'start'`
  * `df.loc[9843, 'eventtype'] = 'start'`

  * 행 삭제 없이 `eventtype` 결측치 0건 달성 (전체 프로세스 라이프사이클 무결성 100% 확보).

### 업무 task_group(접수·현장·정산), 주체(SUBJECT: 사람·시스템), 외주 여부 분류
