## 1. 과제 배경 및 데이터 정의

* **데이터셋**: `repair2.csv`
* **도메인**: 네덜란드 임대 주택 기관의 집 수리 요청 처리 프로세스 데이터
* **단위 정의**:
  * **1개 `caseID`** = 1건의 집 수리 요청 (사건)
  * 각 접수 건에 대해 여러 **`taskID` (업무)**를 각 **`originator` (작업자)**가 수행하며 프로세스 진행
* **컬럼 명세**:
  * `caseID`: 집 수리 요청 접수 번호
  * `taskID`: 업무명
  * `originator`: 업무 담당자
  * `eventtype`: 업무의 시작(`start`)과 끝(`complete`) 표시
  * `contact`: 집 수리 요청의 접수/요청 채널
  * `RepairType`: 수리 방식
  * `objectKey`: 수리 대상 집 식별 Key
  * `RepairInternally`: 내부 수리 여부 (`True`/`False`)
  * `EstimatedRepairTime`: 예상 수리 시간
  * `RepairCode`: 수리 종류 코드
  * `RepairOK`: 수리 정상 종료 여부 (`True`/`False`)
  * `date`: 업무 수행 일자
  * `time`: 업무 수행 시각

## 2. 필수 분석 과제 및 평가 질문

### 질문 1. 기본 분석 및 데이터 전처리

* 기본 데이터 탐색(EDA) 및 결측치, 이상치, 타입 변환 등 데이터 전처리 수행
* 전처리 기준 및 전처리 결과에 대한 명확한 설명

### 질문 2. 상세 분석 및 프로세스 분석 (핵심 평가 영역 ⭐)

1. **AS-IS 프로세스 흐름 설명**: 현재 수리 프로세스가 표준적으로 어떻게 흘러가고 있는지 (주요 경로 및 흐름도)
2. **프로세스 문제점 도출**:
   * **병목 현상 (Bottleneck)**: 어느 단계 사이에서 대기시간(Waiting Time)이 가장 심각한가?
   * **반복 작업 (Rework / Loop)**: 동일 케이스 내에서 불필요하게 재작업되거나 반복되는 업무는 무엇인가?
3. **소요 시간 영향 요인 분석**:
   * 전체 케이스 완료 소요 시간(Lead Time)에 유의미한 영향을 미치는 데이터 요소(수리방식, 담당자, 채널 등) 제시 및 데이터 근거 제시

### 질문 3. 프로세스 개선 방안 (TO-BE 전략)

* 발견된 문제점(병목, 재작업, 지연 요인)을 실질적으로 해결할 수 있는 데이터 기반의 구체적 개선 방안 및 기대 효과 서술

## 3. 평가자(퍼즐데이터) 관점의 핵심 성공 요인 (Key Success Factors)

> **💡 중요**: 퍼즐데이터(PuzzleData)는 프로세스 마이닝(Process Mining) 전문 기업.
> 단순 통계치(평균, 합계) 나열을 지양하고, **프로세스 마이닝 관점(케이스 리드타임, 대기시간 vs 순수작업시간, 병목 경로, 재작업 루프)**을 명확하게 제시하는 것이 핵심 차별화 포인트.
